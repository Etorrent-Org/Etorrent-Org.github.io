La Factory

Créer une app sans reconstruire toute la mécanique.

Le framework sépare la définition métier, le parcours de validation et la production des livrables. Use Case IA, Story Mapper, H9 Bench et les futures apps H9 peuvent ainsi partager le même runtime.

01

Définir visuellement

Champs, critères pondérés, vues résultat et exports sont décrits dans une définition d’application importable.

  • Formulaires
  • Kanban
  • Mind map
02

Valider à deux moments

L’utilisateur corrige le préremplissage avant la génération, puis conserve la maîtrise des résultats et des passerelles entre apps.

  • Correction
  • Approbation
  • Traçabilité
03

Produire depuis le structuré

La synthèse et les livrables sont validés par schéma. Les fichiers sont ensuite reconstruits sans demander à l’IA de fabriquer des binaires.

  • MD
  • PDF
  • PPTX
  • XLSX

Parcours commun

Cinq étapes, une source de vérité.

Le runtime orchestre la progression. PostgreSQL conserve les demandes et les jobs ; les runners CLI restent isolés dans l’environnement Docker.

  1. 01

    Exprimer

    Décrire librement le besoin métier et le contexte de l’application.

  2. 02

    Préremplir

    Transformer le brief en formulaire structuré avec le moteur choisi.

  3. 03

    Valider

    Corriger les hypothèses et approuver explicitement les données.

  4. 04

    Générer

    Produire la synthèse et les livrables dans l’enveloppe H9.

  5. 05

    Exporter

    Reconstruire les formats utiles depuis les données validées.

Les applications H9 n’appellent pas directement les API OpenAI ou Mistral. Le runtime s’appuie sur des runners CLI internes authentifiés dans l’environnement Docker. Cette architecture est conçue pour un usage local et maîtrisé — pas pour une exposition publique en SaaS.
